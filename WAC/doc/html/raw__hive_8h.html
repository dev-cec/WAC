Extrait les fichiers d'un répertoire par lecture brute NTFS.

Un répertoire absent n'est PAS une erreur : c'est le cas nominal en collecte (tous les profils n'ont pas tous les dossiers). Il rend alors 0 fichier.

Paramètres
volumeLetterlettre du volume, ex. L"C"
dirPathOnVolumechemin du répertoire sur le volume
outDirrépertoire de sortie local (créé si absent)
extensionsextensions à retenir, point compris et casse indifférente (ex. { L".pf" }) ; liste vide = tous les fichiers
extracted(optionnel) reçoit le nombre de fichiers effectivement extraits
diagnostic(optionnel) reçoit un état lisible de l'énumération : « absent », « vide », « N entrée(s), M retenue(s) ». Sans lui, un décompte à 0 ne dit pas si le répertoire manque, s'il est vide, ou si le filtre d'extension a tout écarté — trois causes très différentes.
releve(optionnel) reçoit un relevé par fichier, empreintes comprises, y compris pour les fichiers dont l'extraction a échoué : c'est la source du manifeste de consigne
Renvoie
ERROR_SUCCESS si le répertoire a pu être énuméré (même vide), S_FALSE si au moins un fichier n'a pas pu être extrait, un code d'erreur si le volume est inaccessible

Comme ExtractDirectoryRaw, mais descend dans les sous-répertoires.

Nécessaire pour \\Windows\\System32\\Tasks\, qui est une arborescence : les tâches planifiées y sont rangées par dossier (Microsoft\Windows...), et le chemin relatif fait partie de l'identité de la tâche. L'arborescence est reproduite à l'identique dans outDir.

Paramètres
volumeLetterlettre du volume à lire, sans les deux-points (ex. L"C")
dirPathOnVolumechemin du répertoire sur le volume
outDirrépertoire de destination ; l'arborescence y est reproduite
extensionsextensions à extraire (vide = toutes)
extractedreçoit le nombre de fichiers extraits
profondeurMaxgarde-fou contre une arborescence cyclique ou anormale (un index NTFS corrompu pourrait boucler) ; 0 = pas de descente
releve(optionnel) reçoit un relevé par fichier, empreintes comprises : c'est la source du manifeste de consigne
Renvoie
ERROR_SUCCESS si l'énumération a abouti (même sans fichier), S_FALSE si au moins un fichier a échoué, un code d'erreur si le volume est inaccessible

Extrait plusieurs fichiers en UNE seule ouverture de volume (efficace).

Paramètres
volumeLetterlettre du volume a lire, sans les deux-points (ex. L"C")
itemspaires {chemin sur volume, fichier de sortie}
perItem(optionnel) reçoit le HRESULT de chaque item, dans l'ordre
releve(optionnel) reçoit un relevé par item, empreintes comprises. C'est la source du manifeste de consigne : sans lui, une pièce est copiée sans rien qui l'identifie.
Renvoie
S_OK si tout réussit, S_FALSE si au moins un item échoue, ou un code d'erreur si l'ouverture du volume échoue.

Énumère le contenu d'un répertoire par lecture brute NTFS. Les noms courts 8.3 sont écartés : NTFS enregistre souvent deux entrées pour un même fichier (espace de noms DOS et Win32), ce qui produirait des doublons.

Paramètres
volumeLetterlettre du volume, ex. L"C"
dirPathOnVolumechemin du répertoire, ex. L"\\Windows\\Prefetch"
outreçoit les entrées trouvées (vidé au préalable)
Renvoie
ERROR_SUCCESS, ou un code d'erreur Win32/applicatif
