Detailed Description

The FAT and exFAT volumes of the machine — a suspect's USB keys and memory cards included —, read raw (fat_volumes.json).

WHAT IT PROVES. What a key holds and what was deleted from it, with the dates the file system kept: a document copied to a key, a tool run from it, a folder removed before the seizure. Deleted entries are listed with what survives of them (fat_volume.h).

HOW. The collection reads each volume raw — never through its file system, which would update access dates — and copies only its metadata (boot sector, FAT, directories) into the exhibit store, as X:\$FatMetadata; the conversion reads that copy, not the volume. Files' contents are not copied. The volume holding the collection is left out.

DATES. One instant must read the same in every artefact: each date is given in UTC (CreatedUtc…) and in the examined machine's local time derived from it (Created…), with the offset in force at that instant — the rule of every local date of WAC. FAT keeps local time, computed by Windows with the offset of the moment it WROTE the date. For a creation, or a modification made on the volume, that moment is the date itself. A modification earlier than the creation is a date kept by a copy (Explorer, robocopy, Copy-Item): written at the copy, which the creation dates, it is converted with the offset in force at the creation, and said so (ModifiedWrittenAt "Copy", ModifiedOffsetApplied, ModifiedAsStored). A winter file copied onto a key in summer is otherwise an hour off — measured in the test VM. exFAT keeps the offset it wrote (CreatedOffset…): the UTC date is exact.
