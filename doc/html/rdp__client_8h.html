Detailed Description

Outgoing Remote Desktop connections: the servers each profile reached, its connection files, and its bitmap cache.

WHAT THE ARTEFACT PROVES. An intruder who moves from this machine to another by RDP leaves, in the profile that ran mstsc.exe:

  • in NTUSER.DAT, Software\\Microsoft\\Terminal Server Client: the recent connections (Default\\MRU0…, the most recent first) and one key per server reached (Servers\\<host>), with the user name offered (UsernameHint), the hash of the certificate accepted (CertHash) and the key's last write — about the last connection to that server;
  • the connection files (*.rdp) in the profile's Documents, Default.rdp among them: the settings of the last connection, its address and user;
  • the persistent bitmap cache, in AppData\\Local\\Microsoft\\Terminal Server Client\\Cache: pieces of the remote screen as the client drew it — what the intruder saw there.

THE CACHE FILES. Cache<NNNN>.bin (RDP 8 and later, the graphics pipeline of Windows 10 and 11) is read: the header "RDP8bmp\\0" and a version on four bytes, then tiles, each a header — two keys, width and height on two bytes each — and its pixels, 4 × width × height bytes, BGRA, rows from the top. Each tile is exported as a BMP image next to the JSON (rdp_cache\\<SID>\\<file>\\tile_<NNNN>.bmp); the JSON gives its size, keys and the SHA-256 of its pixels. The format was established on a session of the test VM and confronted with bmc-tools (ANSSI) tile by tile. The older bcache2*.bmc (compressed tiles of the RDP 6/7 drawing orders) are collected but not decoded: the test VM writes them empty, and nothing is decoded without a sample to check it on.
