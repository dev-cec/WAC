Detailed Description

Decryption of the SAM password hashes, for an offline investigation.

WHY. A weak or empty password used by an attacker makes the intrusion look like a legitimate logon. WAC converts the hashes to JSON so that WAE can confront them, after the fact and offline, with the hashes of empty or common passwords. WAC itself judges nothing: it only converts.

THE CHAIN. The hashes are not stored in the clear. Three layers come off:

  1. the machine's boot key (syskey), scrambled across four class names of SYSTEM\\CurrentControlSet\\Control\\Lsa (JD, Skew1, GBG, Data);
  2. the SAM's hashed boot key, in SAM\\Domains\\Account value F, protected by the boot key — RC4 on older systems, AES-CBC since Windows 10;
  3. each account's NT and LM hash, in its V value, protected by the hashed boot key (RC4 or AES), then by a last DES layer keyed on the RID.

The password hashes themselves are one-way: they are condensates, not the passwords. They identify a password without revealing it, which is exactly what WAE needs to flag a weak one.
