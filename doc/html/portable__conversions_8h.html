Detailed Description

The conversions that need no system: little-endian integers, read and written — the byte order of every on-disk Windows format —, bytes as hexadecimal text, UTF-8 as UTF-16, base64.

Without windows.h, so that the modules built and checked outside Windows (sha.cpp, authenticode.cpp, the archive readers) use the same functions as the rest; conversions.h includes it.

T readLittleEndian ( const uint8_t *  p)

An unsigned integer stored little-endian, as every on-disk Windows format holds them, read without alignment requirement. The ONE reader for new code and the old alike: the thirteen per-module copies (rd16, rd32, rd64, two of them copied word for word between pe_resource.cpp and wevt.cpp) came back to it (backlog B-030), then the ones named otherwise: lu16 and lu32 of authenticode.cpp, read8 to read64 of evtx.cpp, archiveLe16 and archiveLe32 of the archive readers (B-044).

UTF-8 bytes as UTF-16 text, without the system's API: a module that must stay verifiable outside Windows (wevt.cpp) cannot call MultiByteToWideChar. A malformed sequence (bad continuation, overlong form, surrogate, beyond U+10FFFF, cut at the end) gives U+FFFD and the reading goes on at the next byte, as MultiByteToWideChar does.
