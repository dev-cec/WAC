Detailed Description

DELETED FILES: the content a deleted file still has on the disk, recovered by raw reading (deleted_files.json, backlog B-036).

WHY. mft.json lists the deleted files whose record NTFS has not reused, and usn_journal.json the deletions — not their content. Yet the tool, the script or the archive an intruder removed is often still on the disk: its clusters stay as they were until NTFS gives them to another file. Read raw (\\.\X:), they leave no trace on the examined machine: no file opened by the system, no recovery tool installed or run there, nothing written to the volume.

LEVEL 1 — THE $MFT'S DELETED RECORDS. A deleted record keeps its unnamed $DATA attribute: resident (the content in the record itself, a few hundred bytes), or the list of its clusters. Each cluster is checked FREE in $Bitmap before it is read and again after: one NTFS gave to another file in between holds that file's data, which would pass for the deleted one's — false and valid in appearance. Such a cluster is a hole, zeros in the copy, and its range is listed: the content is published as PARTIAL, never as recovered. Clusters read back all zero — what a solid-state drive returns once Windows sent it TRIM — are declared ZEROED, not copied.

WHERE WINDOWS 10 PUTS THEM. A file deleted while a handle is still open on it — an antivirus, the indexer — is renamed into $Extend$Deleted, then freed at the last close: its record names it there. Measured on Windows 11: every witness the harness deleted. The conversion gives the path it had (FormerPath) and the deletion's time (DeletedUtc), from the change journal of the collection.

WHICH FILES. Every deleted file of every fixed NTFS volume but those of the folders excluded_folders names (wac.yml: WinSxS, Windows Update…, deleted by the thousand and of no intruder), the collection's own output folder, and files without content. The most recent first — the latest date their record carries, the deletion's being nowhere in it —, until max_total_mib is copied — the files the bound leaves out listed as NotRead, not omitted —; a file beyond max_file_mib is read for its fingerprints, not copied.

WHAT IS COPIED. An executable recovered is judged as the volume's are (binaires.h, binary: of wac.yml): an authentic one is fingerprinted, not copied; any other is copied. Documents, scripts, archives are copied. In the exhibit store, a content goes under X:\$DeletedFiles\<record>-<sequence>_<name>, never under its former path: a file of the same name may exist there now.

WHEN. The selection and the reading are the collection's: the $MFT read is the working copy of the collection's own (ExtractNtfsMetadataRaw), each record read again on the volume before its clusters — reused since, it is said so. What was found is a sealed snapshot (live_snapshot.h), which the conversion writes as deleted_files.json.

Enumerator

some clusters given to another file: holes of zeros, listed

Overwritten 

every cluster given to another file: nothing recovered

Zeroed 

the free clusters read back all zero (TRIM): nothing to trust

NotRecoverable 

compressed, encrypted, runs elsewhere or forged: not read
