Detailed Description

The thumbnail and icon caches of Explorer: what each user had on screen, even after the file itself was deleted.

WHAT THE ARTEFACT PROVES. Explorer keeps, per profile, in AppData\\Local\\Microsoft\\Windows\\Explorer, the thumbnails it drew (thumbcache_<size>.db: pictures, videos, documents seen as large icons or in the preview pane) and the icons of the programs it showed (iconcache_<size>.db). A thumbnail stays after the file is deleted: it shows what the user had under his eyes.

THE FORMAT, "CMMM" (Windows 8 to 11, versions 0x1E to 0x20). A file header of 24 bytes — signature, version, cache type (its size: 16, 32, 48, 96, 256… pixels), the offset of the first entry and of the first free place — then entries of 56 bytes: signature, size, 64-bit hash, length of the identifier, padding, size of the data, width, height, data checksum, header checksum; then the identifier (the hash in hexadecimal, or a shell name), the padding, and the image itself: BMP, PNG or JPEG. The hash is the file's System.ThumbnailCacheId, which Windows gives for a file through its property system: it ties a thumbnail to its file. Vista and 7 lay their entries out otherwise: they are not decoded (backlog B-037).

THE CHECKSUMS are the format's own control, recomputed for every entry: a CRC-64 (reflected polynomial 0x92C64265D32139A4, the table of thumbcache.dll) over the first 48 bytes of the entry for the header; for the data, over at most its first 1,024 bytes, XOR, beyond them, a second CRC of four bytes every 400. Both were checked on every entry of the test VM's caches; an entry whose checksum fails is still given, and says so.
