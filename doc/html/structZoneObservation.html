Detailed Description

What a Windows before Windows 10 logs of its time zone — it writes no Kernel-General 22 nor 24. Measured on Server 2008 R2, 2026-11-10:

  • EventLog 6013, at each boot and once a day: the zone in force, as its STANDARD offset and standard name (the last datum, "-60 Paris, Madrid", localized: Windows 11 in French). The standard offset, not the one in force: -60 for Paris in October, in summer time — daylight saving comes from the zone's rules. Server 2003 writes none, but the same datum in EventLog 6005 and 6006, at each boot and each shutdown (measured);
  • TZUtil/Operational 20001: a zone set by tzutil, its key name, at the instant of the change;
  • Kernel-General 1 with NewTime equal to OldTime: a zone set through the API (SetDynamicTimeZoneInformation, as the Control Panel does), at the instant of the change, without its name. A clock really set, or adjusted at boot (by 0.125 ms, measured), changes the time: not one. tzutil writes one too, with its 20001: within a second of a 20001, the same change.
