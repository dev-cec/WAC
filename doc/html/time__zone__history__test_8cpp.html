Detailed Description

The offset in force when a local time was written, from the System log (time_zone.h: timeZoneHistoryFrom, biasAtLocalLogged).

WHY THIS TEST. A local time read with the current zone's offset, when the zone was another when it was written, gives a valid date hours off: the NetSetup.LOG of Server 2025, written in the Pacific time of its installation, came out 8 h off. The cases here are those the test VMs showed, 2026-11-09, and those of a zone set back or forward.

Usage: time_zone_history_test [<SYSTEM hive> <SOFTWARE hive>] — built by build-windows.sh --test, runs under Wine. With the hives of a Windows before Vista (Server 2003's, taken offline from its disk), also the current zone's key name deduced from its StandardName: SYSTEM holds no TimeZoneKeyName there. Exit code: 0 if all checks hold.
