Detailed Description

Paths longer than MAX_PATH: the extended form, and the operations on folders and files that hold with it.

WHY. An exhibit is stored under its original path, below the output folder: <output>\exhibits\C\Users\…. A path of 230 characters on the examined machine — a deep node_modules, an application's profile — passes MAX_PATH (260) once there, and Windows refuses it unless it is written in the extended form \\?\C:\…: 482 exhibits of a full kit were lost so (0x8007001d, backlog B-049). Declaring the program longPathAware is not enough: it also needs LongPathsEnabled in the registry, off by default, and WAC writes nothing on the examined machine.

WHY NOT std::filesystem. Measured in the test VM with g++ 13 (MinGW-w64): on an extended path, the streams and file_size work, but create_directories loops forever, copy_file fails ("File exists", overwrite asked), relative and root_name give nothing, and a directory iteration does not give the folder's files. Folders, copies, moves, walks and deletions therefore go through Win32 here; a stream is opened on extendedPath(path).

Header-only and without WAC's other headers, as whole_file.h, which uses it.

◆ extendedPath()

std::wstring extendedPath ( const std::wstring &  path)
inline

The form of path that Windows opens whatever its length.

A path whose ABSOLUTE form is shorter than the limit is returned AS IS: what is written, logged and recorded keeps its ordinary form, and the APIs that do not accept the extended one (some take a path from WAC: esent, the offline registry) never see it on a common path. The absolute form decides, not the path as given: Windows applies the limit after resolving it, and a relative "out\working\…" of 241 characters failed once under C:\wactest. A longer one is made absolute (GetFullPathNameW, which also turns / into \ — the extended form takes no /, no ., no ..) and prefixed: \\?\C:\…, or \\?\UNC\server\share\….

Parameters
patha file or folder, absolute or relative to the current folder
Returns
the path to give Windows

Every file below a folder, whatever the depth, with its path RELATIVE to the folder ("a\b.txt"): each folder's files, then its subfolders in the order Windows lists them. A subfolder that cannot be listed is skipped, the walk goes on: std::filesystem's iteration stopped at the first error, and a deep folder ended it before the system hives were reached (B-049).
