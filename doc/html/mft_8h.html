Detailed Description

THE $MFT of the system volume: every file, present or deleted, with its dates — the base of the file system's timeline.

WHY. Each file and directory of an NTFS volume has a record in the $MFT, which keeps it after deletion until NTFS reuses it. A record carries two sets of four dates:

  • $STANDARD_INFORMATION (creation, modification, record change, access): what Explorer shows, and what SetFileTime rewrites — a tool that antedates its own files ("timestomping") changes these;
  • $FILE_NAME: written by NTFS itself when the file is created, moved or renamed, out of reach of SetFileTime. A $STANDARD_INFORMATION earlier than its $FILE_NAME betrays a forged date. Together with the change journal (usn_journal.h), they give the timeline of the machine's files: what was dropped, when, and what was removed.

READ FROM THE EXHIBIT. The $MFT is copied raw by the collection (ExtractNtfsMetadataRaw, raw_collect.h) and read here from the exhibit store, in place: a conversion on an analysis workstation reads the same bytes. Up to gigabytes: it is read by blocks, and mft.json is written as it goes (JsonArrayWriter), never held in memory. Only what the paths need is kept — each record's name and parent.

THE PATH of a record is rebuilt from its parent references up to the root. A parent reference carries the SEQUENCE number of the parent record: if the record was reused since, the parent named now is another directory, and the path is marked incomplete rather than made up. A deleted record keeps its content, its sequence number raised by one: that is accepted.

THE DATES are written in UTC only: the timeline tools work in UTC, and the pairs local/UTC of the other artefacts would double a file that already counts one object per file of the volume.
