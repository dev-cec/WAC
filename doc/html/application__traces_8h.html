Detailed Description

THE table of the applications' traces: remote administration, antivirus, messaging, cloud storage, file transfer, VPN, virtualisation, server applications, and the system's and servers' own logs.

WHY A TABLE. Each is a few folders a known product writes, of formats WAC has no decoder of its own for: a line here, rather than a collector each. The files are copied raw, then converted generically (application_trace_files.h): a log line by line, XML, JSON and INI as their structure, the rest listed. wac.yml has one section per group (one artefact of the catalogue) and, under it, one switch per product.

THE SOURCE. KAPE's targets give most paths, an independent list of where these products write. A product is rarely installed on a test machine: a witness proves that the path written here is taken, not that every version of the product writes there. The manuals say so.

WHAT IS LEFT OUT, ON PURPOSE. SSH private keys, which KAPE takes: clear secrets opening other machines, and the public half and the logs tell the story. Files a user keeps in a synchronised folder: the metadata says what was synchronised. Virtual disks and memory: the configuration and logs lead to them.

Portable C++, without windows.h: tested natively (application_traces_test).

◆ expandFolderPattern()

std::vector< std::wstring > expandFolderPattern ( const std::wstring & written,
const std::function< std::vector< std::wstring >(const std::wstring &)> & subfolders )

The folders a written path stands for, each component holding * or ? matched against the subfolders the reading finds (raw_collect.cpp reads the NTFS index). Only the table's own components are patterns: a name found on the disk is taken literally — a forged index naming a folder "Program Files*x" matched its own pattern again, and the expansion recursed without end. A name holding a separator, ".", "..", is not a folder's, left out.

◆ traceOwnerOf()

TraceOwner traceOwnerOf ( const std::wstring & sourcePath)

The product that takes a file, as the collection took it: one of its folders (its * components matching), the file at most depth levels below, its name kept by the filter. A PROFILE_MARK folder stands for that folder in any profile — \Users\<name>, \Documents and Settings\<name>, the system's and the services' profiles. When two lines take the same file, the first of the table wins: the order of the table decides, the same at every conversion.

Returns
