Detailed Description

NTFS security descriptors ($Secure:$SDS): the owner and the access rights of every file.

WHAT THE ARTEFACT PROVES. NTFS keeps each distinct security descriptor ONCE, in the $SDS stream of the metafile $Secure; a file's $STANDARD_INFORMATION only holds its number (SecurityId, in mft.json). The descriptor names the file's OWNER — the account that created it, or took it over — and its DACL says who may read, write or run it. An intruder's tool dropped by their account, a system file whose owner is no longer TrustedInstaller, an ACL opened to Everyone: all are read here, for every file of the $MFT, deleted ones included while their record lasts.

ONE ENTRY PER DESCRIPTOR, NOT PER FILE. Thousands of files share a descriptor; security_descriptors.json gives each once, and mft.json the number that points to it (Volume + SecurityId).

THE FORMAT ($SDS). 256 KiB blocks, each followed by its mirror copy (the odd blocks are skipped). An entry: hash (4), SecurityId (4), its own offset in the stream (8), its length header included (4), then the self-relative descriptor; entries are aligned on 16 bytes and never cross a block. An entry whose recorded offset is not its place, or whose length leaves the block, ends the block's reading.

A CHECK OF ITS OWN. The hash is computed by NTFS over the descriptor's bytes; it is recomputed here, and a descriptor that does not match it is flagged (HashMismatch) rather than trusted silently.
