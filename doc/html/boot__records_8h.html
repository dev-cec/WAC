Detailed Description

THE BOOT RECORDS: what runs before Windows — each disk's first mebibyte, each partition's boot sectors, the EFI system partition's files (backlog B-052).

WHY. A bootkit runs before the system that could see it: it rewrites the master boot record or a volume's boot code (BIOS machines), hides its code in the sectors before the first partition, or replaces a boot loader of the EFI system partition (BlackLotus, CosmicStrand's chain) — ATT&CK T1542 "Pre-OS Boot". None of it is in a file the system shows: the EFI partition has no letter, the sectors no file. Read raw, they are kept as they were, for the analysis to confront with known boot code and with the signatures of the loaders.

WHAT IS COPIED, from each physical disk read raw (\\.\PhysicalDriveN, opened for reading; the disk holding the collection medium is left out):

  • its first mebibyte: the MBR (boot code, partition table, disk signature), the GPT header and entries, and the gap before the first partition, where a bootkit's code hides;
  • the first 16 sectors of each partition: its boot sector and, for NTFS, its initial program loader;
  • every present file of each EFI system partition (GPT type C12A7328-F81F-11D2-BA4B-00A0C93EC93B, or MBR type 0xEF), read through WAC's own FAT reader — the boot loaders, their configuration (BCD), their certificates' revocations. Logical partitions of an extended MBR partition are not followed: their tables lie past the first mebibyte, and Windows boots from a primary one.

The conversion (boot_records.json) reads the copies: the partition table decoded, in sectors as it is stored, the SHA-256 of the MBR's boot code and of each boot sector, each EFI file with its size and SHA-256.
