Detailed Description

Reading of an SQLite database collected from the examined machine (browsers, timeline).

NEVER THE EXHIBIT ITSELF. A database is opened on a PRIVATE COPY, made in the working directory with its -wal or -journal when they were collected beside it. SQLite then does what the application would have done at its next start: it replays the write-ahead log — the last visits of a browser that was running are often only there — or rolls back the transaction a hot journal left unfinished. That needs write access, which the copy gives and the sealed exhibit must never give; the copy is deleted when the database is closed. The same principle as the hives, whose logs are replayed on the working copy (raw_collect.h).

Every value comes back through SqliteRow, read by column and type: a text column decoded from UTF-8, an integer, a BLOB with its size. A database whose schema is not the one expected (a column missing in an older version) is detected by the query's preparation failing: logged, and the caller's artefact keeps what it could read.
