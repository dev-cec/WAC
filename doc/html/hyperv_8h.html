Detailed Description

The Hyper-V role: the virtual machines a host declares.

WHAT THE ARTEFACT PROVES. A virtual machine on a host is a machine out of the sight of the host's own defences (ATT&CK T1564.006): its name, and above all its disks, wherever they are. A disk image is not taken: its paths lead to it.

WHERE, measured on Server 2022: ProgramData\Microsoft\Windows\Hyper-V:

  • data.vmcx: the host's list, the configuration of each machine wherever it is;
  • Virtual Machines\<id>.vmcx, Snapshots\<id>.vmcx: each configuration. The .vmrs and .vmgs beside them hold the state of a running machine, its memory among it: not taken. Server 2012 R2 and before write .xml in the same folders: copied raw, not converted, not measured.

THE .vmcx FORMAT IS NOT DOCUMENTED. What was measured: a text key is one byte of length (its zero included), the key, a zero, then for a text value 4 bytes of length and that many bytes of UTF-16, without final zero; the whole tree is held twice, in two log-like copies. Its links between nodes are not reconstructed: WAC gives the key and text value pairs as found, each once. So it cannot say which name is the machine's, among those of its devices: the reader of the JSON does. Numbers (memory, processors) are not read.
