Detailed Description

THE CHANGE JOURNAL of the system volume ($UsnJrnl:$J): what happened to which file, and when.

WHY. NTFS records every change to a file — creation, write, rename, deletion, attribute or security change — as a record of its change journal, for the indexer and the backup tools. The journal keeps weeks of activity where the $MFT only shows the last state: a tool dropped, run, then deleted leaves here its creation, its renames and its deletion, dated to the 100 ns. With the $MFT (mft.h), it is the timeline of the machine's files.

A record names the file and the directory holding it by their $MFT references: the full path is rebuilt from the $MFT of the same collection (Mft::pathOf). A directory deleted and reused since cannot be named: the path then keeps what is known, and says it is incomplete.

READ FROM THE EXHIBIT. The stream is copied from its first allocated byte (ExtractStreamRaw): the record numbers (USN) are offsets in the whole stream, restored with the offset the manifest records (LeadingSparseBytes). Records of version 2 and 3 are decoded; version 4 (ranges of a file written, when range tracking is on) carries no name and is counted, not converted.

THE DATES are written in UTC only, as mft.json and for the same reason.
