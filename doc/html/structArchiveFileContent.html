A file or folder inside an archive, as Explorer shows it. THE LAYOUTS. A ZIP is read by Explorer's own ZIP folder: the date is a text, at 0x24 since Windows 10 at least, at 0x18 under Windows XP, and the layout is told by finding a date there. Any other archive Windows 11 opens (7z, tar…) is read through libarchive, whose item holds a FILETIME and the name (isReaderArchiveItem). The bytes at 0x08 and 0x10 are the entry's sizes, not dates: they were read as a FAT date and as a FILETIME, which gave, for any file with content, a date taken from its sizes and the date text in place of the name (B-029, a real machine's "\x10\x01 01/01/1980 00:00:00"); a folder, emulated by Explorer, has no sizes, which hid the defect on the test VM. THE DATE HAS NO TIME ZONE. It is the archive entry's own date — a ZIP entry keeps the clock time of the machine that made the archive — which Explorer copies as it is. Measured on the test VM (B-028): an entry dated 13:00 in a ZIP gives 13:00 here, whatever the zone it was made in. It is given as written, without offset.
