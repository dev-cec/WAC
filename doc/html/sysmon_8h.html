Detailed Description

SYSMON, where it runs: its configuration, read in the examined SYSTEM hive, and the files it archived (backlog B-053).

WHY. Sysmon (Sysinternals) is not part of Windows, but where it is installed its log is often the best detection source of the machine: processes with their command line and fingerprints, connections, drivers loaded, accesses to LSASS. Its log is converted with the others (events.json), even moved (event_log_files.h). What it does not say is what Sysmon was told to watch — so what its silence proves —, nor what it kept of the files deleted under a FileDelete rule: their content itself, an intruder's tool erased from the disk.

WHERE. Two keys of SYSTEM\<ControlSet>\Services, both renamable at installation (sysmon -i -d <driver>, a renamed executable):

  • the service (Sysmon64, Sysmon): ImagePath, and Parameters\DriverName, the name of its driver's key;
  • the driver (SysmonDrv): Parameters holds the configuration — Rules (the rules compiled, a binary format Sysinternals does not document, given as stored with its SHA-256), HashingAlgorithm, Options, ArchiveDirectory, ConfigFile (the XML installed from) and ConfigHash (its fingerprint then). An installation is told by that link — a service whose DriverName names a key whose Parameters hold Rules —, not by a name: renamed, it is found all the same.

THE ARCHIVES. ArchiveDirectory is a folder at the root of the system volume ("\\Sysmon\\", the default, when the value is absent); each file is named by its fingerprint, with its extension. Taken whole, raw, with the XML of ConfigFile when it is still there. The version of Sysmon is not read here: its event 4 ("Sysmon service state changed") carries it, and the binary of the service is fingerprinted with the other binaries.
