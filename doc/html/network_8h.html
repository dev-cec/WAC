Detailed Description

THE NETWORK STATE of the examined machine, observed live: who talks to whom, and through what.

WHY. A connection to a command server, a port opened by an implant, a gateway or a DNS server changed to intercept the traffic: none of it is in a file or a hive. Only the running system knows it, at the moment of the collection. Four tables, in the order an analyst reads them:

  • Connections: TCP connections and UDP ports, IPv4 and IPv6, their state, the process that owns each (its PID, named at conversion from the processes observed) and WHEN each was created — Windows keeps that time, and it dates a connection the process list alone does not;
  • Neighbours: the ARP (IPv4) and NDP (IPv6) caches — the machines of the local network this one spoke with lately, a lateral movement's trail;
  • Interfaces: addresses, gateways, DNS servers, DHCP;
  • Routes: the routing table, where a route added to divert traffic shows.

THE FOOTPRINT. Reads of the TCP/IP stack's state, through iphlpapi: in-memory queries, no packet sent, no event logged. iphlpapi.dll is loaded at run time, from System32, and only when this artefact is asked for (wac.yml, artefacts.network): WAC.exe imports no network library, and Winsock is not used at all — the addresses are formatted by WAC (ip_address.h).

WHAT IT DOES NOT SEE: a connection already closed (its trace, if any, is in the event logs), nor one a kernel rootkit hides from the stack's tables. Recorded as a sealed live snapshot (live_snapshot.h), converted here or on an analysis workstation.
