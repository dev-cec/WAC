Detailed Description

The web servers other than IIS, and the database engines of the examined machine (backlog B-035, lot 3): Apache, nginx, MySQL and MariaDB, PostgreSQL.

FOUND WITHOUT RUNNING ANYTHING. Nothing registers these products in a place of their own. A service says where its binary is (Services\<name>\ImagePath, or Parameters\Application for one wrapped by NSSM); a server started by hand has none, and is looked for by the folder its archive unpacks to: \Apache24, \nginx-1.28.0, \xampp\apache, \Program Files\Apache Software Foundation\Apache2.4.

THE CONFIGURATION says what runs and from where: Apache's httpd.conf with its Include and IncludeOptional (Defined variables expanded), nginx's nginx.conf with its include. Read as written, a conditional section (<IfModule>, <IfDefine>) included: what it holds is on the disk, whether or not the condition held. An include is followed to 16 levels, each file once, in what the collection copied: one outside it is said, not read.

THE LOGS. Access logs in the common and combined formats, the default of both products, whose date carries its offset: converted to UTC exactly. Error logs in the three layouts met — Apache 2.2, Apache 2.4, nginx — whose date is local without offset. A line in another format is given raw, never dropped. Apache 2.4's own ErrorLogFormat can make any layout: raw too.

THE DATABASE ENGINES are taken raw, not decoded: the data folder whole up to max_database_mib of wac.yml; above, its configuration and logs alone, and said (raw_collect). Their files are read through the volume, a running engine locks nothing that way. The binary is mariadbd.exe or mysqld.exe (MariaDB 10.5 renamed it, and keeps both); PostgreSQL's service names its folder (pg_ctl runservice -D), MySQL's its option file, whose datadir says the rest. Logs and write-ahead files lie in the data folder, whatever their name (pg_log or log, pg_xlog or pg_wal, before and since version 10).

OUTPUT. web_server_installations.json, web_server_database_engines.json, web_server_error_logs.json; the access logs join web_server_logs.json.
