Detailed Description

The browsers' sessions: Chromium's SNSS files (Session_*, Tabs_*) and Firefox's mozLz4 (.jsonlz4) files, decoded.

WHAT THEY PROVE. A browser keeps, beside its history, what was OPEN: the windows and tabs of the current and the last session, each tab's pages back and forward, and the tabs and windows the user closed. A page read in a private window leaves no visit, and a history the user cleared none either; the session file may still hold the tab, its title and when it was shown. KAPE collected these files and WAC did not (backlog B-048).

CHROMIUM, SNSS. Sessions\Session_<time> and Sessions\Tabs_<time>: a header ("SNSS", a version) then commands, each a 16-bit size, an 8-bit identifier and its payload. The payload that matters is the navigation, a base::Pickle (a 32-bit payload size, then 32-bit-aligned fields) written by SerializedNavigationEntry::WriteToPickle: tab, index, URL, title (UTF-16), page state, transition, type mask, referrer, referrer policy, original URL, user agent override, time (microseconds since 1601, UTC), search terms, HTTP status. Its command identifier is 6 in a Session file (SessionService) and 1 in a Tabs file (TabRestoreService), where command 4 gives, for a closed tab, the navigation shown and the instant it was closed. A file is a log: a later command for the same tab and index replaces the earlier one.

FIREFOX, mozLz4. "mozLz40\0", the decompressed size on 32 bits, then one LZ4 block (the block format, without the frame): sessionstore.jsonlz4, the backups of sessionstore-backups and of bookmarkbackups are JSON compressed so.

Every read is bounded by the buffer, never by a length the file states: the files come from the examined machine. Portable C++, without windows.h, for the native test (browser_sessions_test).
