Detailed Description

DPAPI master keys: which keys each user and the system hold, and since when — never the key.

WHAT THE ARTEFACT PROVES. Every secret Windows keeps for a user — saved passwords of the browsers, Wi-Fi keys, the credential manager, cookies — is encrypted with one of that user's DPAPI master keys, themselves encrypted by the user's password (or, for the system, by the DPAPI_SYSTEM secret of the SECURITY hive). The key files are COPIED AS THEY ARE, still encrypted, into the exhibit store: with the password or the system secret, the analysis can decrypt those secrets later (decision of 2026-10-01, B-032).

WHAT THE JSON GIVES. For each key file: the owner (SID, from its folder), the key's GUID, its version and policy, the sizes of its blocks — a domain backup block says the account belonged to a domain — and the file's dates: a key created at an odd hour is a new password, or a new account. The Preferred file names the key in use and when it expires. Nothing of the key material is decoded or emitted.

A CHECK OF ITS OWN. The GUID written in the header must be the file's name; a file whose header does not say so is listed without its fields.

Sources: <profile>\\AppData\\Roaming\\Microsoft\\Protect\\<SID>\\ and \\Windows\\System32\\Microsoft\\Protect\\S-1-5-18\\ (machine keys, and User\\ for the system account's own); CREDHIST, the history of the user's previous passwords, is copied raw beside them, not converted.
