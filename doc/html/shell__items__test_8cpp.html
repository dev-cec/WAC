Detailed Description

Checks the decoding of the shell items of an archive's content (ARCHIVE_FILE_CONTENT), and that it never reads outside the item.

WHY THIS TEST. The item's bytes at 0x08 and 0x10 are the archive entry's sizes; they were read as dates, so that a file inside a ZIP came out with a date made of its sizes and the date text in place of its name (B-029). A folder, which has no sizes, decoded right and hid the defect.

Inputs:

  • a folder's item as Explorer wrote it on the test VM (Windows 11), read from its BagMRU: the reference, with the values the VM's witness gave;
  • a file's item, the same layout with its sizes, method and CRC-32 (libfwsi, "Compressed folder shell item", Windows 10);
  • the same without a date ("N/A"), and the Windows XP layout (libfwsi; Zimmerman's Lnk library, ShellBagZipContents, which SBECmd uses);
  • a folder of a 7z and of a tar.gz, as the test VM's Explorer wrote them (Windows 11 reads them through libarchive: another layout, a FILETIME in UTC);
  • every truncation of each, its declared size following, against a PAGE_NOACCESS page (guard_page.h): one byte read outside it stops the test.

Usage (runs under wine): shell_items_test.exe
