Detailed Description

Reader of ESE databases (Extensible Storage Engine, "JET Blue"): SRUDB.dat, qmgr.db, and the other databases Windows keeps this way.

WHY OUR OWN. ESENT's API opens a database for writing and may rewrite its pages, and its reading would depend on the DLL of the analysis workstation. The format is read here, page by page, from the working copy; esent.dll only replays the transaction logs into that copy beforehand (ese_recovery.h), never reads it.

THE FORMAT, as described by J. Metz (libesedb) and Fox-IT (dissect.esedb), checked on the test VM against dissect.esedb on the same files:

  • page 0 is the header (page size at 236, state at 52); logical page n is at (n + 1) × page size;
  • a page: a header of 40 bytes, 80 above 8 KiB; at its end, one tag of 4 bytes per entry (size, offset); an entry is a key (with a prefix shared through the page's first tag) then data — a child page number in a branch, a record in a leaf;
  • the catalog, MSysObjects, rooted at page 4, gives each table its root page, its columns (identifier, type, code page) and its long values' root;
  • a record: fixed columns (identifiers 1–127) with a null bitmap, variable ones (128–255) through an offset table, tagged ones (256 and above) through a table of identifier/offset pairs; a tagged value too large is "separated" into the long-value tree, keyed by its identifier then its offset, big-endian.

COMPRESSED VALUES: 7-bit text (ASCII or UTF-16), met in the Windows.edb of Windows 8.1, is unpacked; XPRESS, met in neither SRUDB.dat, qmgr.db nor that Windows.edb, is said so, with its scheme, rather than guessed. Records whose tagged columns are in the pre-Vista format give their fixed and variable columns only.

A DATABASE COPIED LIVE is in "dirty shutdown" state: what the service changed since its last checkpoint may be only in its transaction logs, which are collected alongside and replayed into the working copy before it is read (ese_recovery.h); a replay not applied is said in the log.

◆ decompressSevenBit()

bool decompressSevenBit ( std::vector< uint8_t > &  value)

Unpacks a value compressed on 7 bits (schemes 1 and 2): after a header byte — the scheme in its high 5 bits, in its low 3 the data bits of the last byte less one —, units of 7 bits packed from the lowest bit: bytes under scheme 1 (of any text, UTF-16 included), UTF-16 characters whose high byte is zero under scheme 2. Measured on the Windows.edb of Windows 8.1, every value confronted with dissect.esedb.

Parameters
valuethe value with its header byte; receives the text's bytes
Returns
false, and the value untouched, for another scheme (XPRESS…)
