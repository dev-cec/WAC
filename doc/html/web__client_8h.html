Detailed Description

The web, client side: what each user did in the Chromium browsers (Edge, Chrome, Brave, Vivaldi, Opera) and Firefox.

WHAT THE ARTEFACT PROVES. The History database of each browser profile holds the pages visited — each visit with its instant, how it was reached (typed, a link, a bookmark, a redirect: Transition) and from which visit —, the terms searched in the address bar, and the files downloaded: where from (the whole chain of redirections, the referrer, the tab), where to, how many bytes, whether the download was flagged dangerous, whether it was opened. A downloaded tool, the page that served it and the user's search before it are read here.

WHAT IS COLLECTED, RAW. For every Chromium profile of every user: History, and beside it the databases this artefact does not convert yet but the analysis may — Login Data (saved logins, their passwords encrypted by the key of Local State, itself protected by DPAPI: see dpapi_master_keys.h), Web Data (autofill), Cookies, Shortcuts, Top Sites, Bookmarks, Preferences —, each with its -journal, -wal or -shm. Never the caches. The databases are read on a private copy (sqlite_reader.h).

WHAT WAS OPEN (B-048). The session files — the tabs open and closed, each page with when it was shown —, the favicons — each site's icon, kept after its history is cleared — and, for Chromium, what was typed in the address bar and the URL then chosen (Network Action Predictor). Firefox's bookmark backups and Internet Explorer's local folder are collected raw, not converted.

TIMES. Chromium counts microseconds since 1601-01-01 UTC — FILETIME's origin, a tenth of its resolution: converted exactly, without a time zone.

FIREFOX. places.sqlite holds the same story under other names — places, visits with a visit type, downloads as annotations of the place they came from — and formhistory.sqlite what was typed in forms and the search bar. Its times are microseconds since 1970 (milliseconds for a download's end). Collected raw beside them: cookies, logins.json and key4.db (saved logins, encrypted), extensions, preferences, the session.

SAVED LOGINS AND COOKIES, NEVER THEIR SECRETS. Chromium's Login Data and Firefox's logins.json say on which sites the user saved a login, under which account name (Chromium keeps it in clear, Firefox encrypted), since when and how often used; the cookies, which sites set one and when it was last sent. Passwords and cookie values are encrypted and are NOT decoded: the databases are in the exhibit store for an analysis that holds the user's DPAPI key (dpapi_master_keys.h).

TYPED URLS. What was typed in Internet Explorer's address bar — and in File Explorer's, which writes there too: TypedURLs of each NTUSER.DAT, url1 the most recent, and TypedURLsTime the instant of each (Windows 8 and later).

WEBCACHE. Internet Explorer, Edge Legacy and the applications built on WinINet keep their history, their cache and their downloads in one ESE database per user, WebCacheV01.dat. Its Containers table names each Container_<n>: History, the daily and weekly MSHist…, Content (the cache: the page or file each entry stored), iedownload, BackgroundTransferApi. Each entry gives its URL and its times as FILETIME — in UTC, EXCEPT the modification time of the MSHist containers, written in the machine's local time: 7,200 s apart from the same entry of History in summer on the test VM. It is converted with the offset in force at its date (suspectLocalToUtc), never read as UTC. The database is copied live, in "dirty" state: what WinINet wrote since its last checkpoint is only in its logs, collected beside it (esentutl /r).

THE CACHED FILES. A Content entry names the file WinINet stored: the container's directory, one of its 8-character subfolders (the SecureDirectories list of the container, indexed from 1 by the entry's SecureDirectory) and the file name, name[1].ext. That is where the HTA that mshta.exe ran, the script a document fetched, lie: Internet Explorer is redirected to Edge on Windows 11, but its engine (WinINet, MSHTML) still serves mshta.exe and the scripts that use it. The cache of each profile (INetCache\IE) is collected, filtered on the types an investigation needs (INETCACHE_EXTENSIONS): its images and style sheets are left.

◆ decodeIeDownload()

bool decodeIeDownload ( const std::vector< uint8_t > &  blob,
Json &  fields 
)

Decodes the record of a download of Internet Explorer 10 and 11 — the ResponseHeaders of an entry of the WebCache's iedownload container, whose format Microsoft does not document. What is read was established on the test VM against a real download by Internet Explorer 11 (Windows 11), each field confronted with what Windows and the witness server say: at 0x50 the file's size; at 0xA0 the server's address (family 2, then IPv4); from 0x158 four UTF-16 strings — MIME type, temporary copy in the cache, URL, then the saved file's full path, or only its suggested name when the user did not save it (IE writes the path when its window closes). The download's instant is the entry's AccessedTime. Measured on 9 real records (sizes 23 and 20, as served). Nothing else is guessed: the FILETIME at 0x24 is not always the AccessedTime, and is left out.

Parameters
blobthe column's bytes
fieldsreceives Url, MimeType, CachePath, TargetPath or SuggestedName, FileSize, ServerAddress
Returns
false if the blob does not have that layout (then nothing is added)
