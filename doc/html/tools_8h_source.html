725// Horodatages ISO 8601
727/* WHY THIS FORMAT. The dates used to be emitted as "15/9/2026 5h43m32s":
728 * neither sortable lexicographically, nor correlatable between tools,
729 * ambiguous on the day and the month, and above all SILENT on the time zone —
730 * and a timestamp without a time zone cannot be used in a timeline.
731 *
732 * ISO 8601 settles all four problems at once: "2026-09-15T05:43:32Z" for UTC,
733 * "2026-09-15T07:43:32+02:00" for a local time. The date then carries its own
734 * time zone: no external convention is needed to read it.
735 *
736 * TWO FUNCTIONS, NOT A FLAG. The suffix ("Z" or "+HH:MM") must tell the truth
737 * about the value. Only the caller knows what it holds, and a parameter with a
738 * default value would produce falsely labelled dates whenever it was
739 * forgotten — a serious fault in an expert report. Hence two named functions,
740 * with no possible default.
741 *
742 * A null date returns an empty string: without that
743 * one would emit "1601-01-01T00:00:00Z" as if it were a real date.
744 */
