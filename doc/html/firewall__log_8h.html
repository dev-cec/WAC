Detailed Description

The Windows Firewall's log, pfirewall.log (backlog B-052).

WHAT THE ARTEFACT PROVES. When its logging is switched on, the firewall writes one line per connection it allowed or dropped: date and time, action, protocol, addresses and ports, size, direction, and the process since Windows 10. It is the only record of network flows a Windows keeps on its disk — what ATT&CK's "Network Traffic Flow" and "Network Connection Creation" otherwise take from a network capture: a connection to a command server, a scan of the local network, an exfiltration. Off by default; a dropped-only log is common. Windows rotates it into <name>.old once it reaches its size limit: both are taken.

WHERE. The LogFilePath of each profile, in the examined hives: the firewall's own settings (SYSTEM …\SharedAccess\Parameters\FirewallPolicy\ <Domain|Standard|Public>Profile\Logging) and a group policy's (SOFTWARE Policies\Microsoft\WindowsFirewall\<Domain|Private|Public>Profile\ Logging); the default besides, System32\LogFiles\Firewall\pfirewall.log (Windows XP: Windows\pfirewall.log), where a log may stay after its path was changed.

THE FORMAT, W3C extended text (w3c_log.h): "#Version: 1.5", "#Software: Microsoft Windows Firewall", "#Time Format: Local", "#Fields: date time action protocol src-ip dst-ip src-port dst-port size tcpflags tcpsyn tcpack tcpwin icmptype icmpcode info path [pid]", then one line per connection. The dates are in the examined machine's local time: converted with its time zone (suspectLocalToUtc), as every local date of WAC.
