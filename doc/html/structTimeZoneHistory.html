Detailed Description

The offset in force over the period the System log covers.

WHY. A local time is right only with the offset of the zone in force WHEN IT WAS WRITTEN. The rules of the current zone know the daylight saving time of each date, not that the zone itself changed: an installation in the default Pacific time, set to Paris afterwards (measured, Server 2025: NetSetup.LOG written at UTC−7, read at UTC+1, 8 h off), a laptop that travelled. Windows writes each change while it runs, and the offset at each boot: within the log, the offset at any instant the machine ran is known exactly.
