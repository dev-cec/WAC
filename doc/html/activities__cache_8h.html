Detailed Description

Windows Timeline: the activities of ActivitiesCache.db, per profile.

WHAT THE ARTEFACT PROVES. The Connected Devices Platform keeps, in LocalAppData%\\ConnectedDevicesPlatform\\<account>\\ActivitiesCache.db (SQLite), what Windows 10 showed in its Timeline: each application opened, file or page viewed (its URI and title in the Payload), the time spent in focus, and — when clipboard history is on — what was copied (ClipboardPayload). <account> is L.<user> for a local account, the account's identifier for a Microsoft or Entra one. Windows 11 dropped the Timeline: the database remains, holding only the synchronised settings — still a trace of the profile's use, with its dates.

TWO TABLES. Activity holds the activities as they now stand; ActivityOperation, the operations not yet sent to the cloud — an activity deleted from Activity may remain there. Both are read, each record carrying its table.

EVERY COLUMN, AS DECLARED. The schema changes between versions of Windows (columns added to both tables since 1803): the rows are read whole and each column is converted by the type its schema declares, not by a list of a given version. A DATETIME is a Unix time in seconds, UTC — given in UTC and in the machine's local time at that date; a GUID, 16 bytes in the order .NET writes them (Guid.ToByteArray). A zero date or GUID is the column's filler, not a value: not emitted. A Payload in JSON is given as the JSON it is; any other blob as text when it is text, in hexadecimal otherwise. The codes (ActivityType, ActivityStatus, OperationType) are given as stored: Microsoft does not document them.

NOT READ. Activity_PackageId repeats the applications of AppId; AppSettings, Asset, Metadata hold no activity. They stay in the exhibit, copied with the database and its -wal (whose last activities SQLite replays on the private copy, see sqlite_reader.h).
