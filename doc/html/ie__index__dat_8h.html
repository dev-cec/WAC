Detailed Description

Internet Explorer 5 to 9's cache files (index.dat): history, cache, cookies, downloads of Windows 7 and earlier.

WHAT THE ARTEFACT PROVES. Before the WebCache (IE 10, Windows 8), WinINet kept one "MSIE Cache File" per kind of record and per user: the history (global, and the daily and weekly MSHist01… folders), the cache of Temporary Internet Files (the URL of each cached file, its server headers, its file in one of the cache directories), the cookies, the downloads. Internet Explorer is still there on the machines it ran on, and its engine served mshta.exe and the scripts of an attack.

THE FORMAT (version 5.2), as libmsiecf (J. Metz) documents it: a header of 72 bytes and the cache directories' names; a chain of HASH tables whose entries point at the records; records in 128-byte blocks from 0x4000 — URL (an entry), REDR (a redirection), LEAK (an entry dropped from the cache but not erased). A URL or REDR record that no hash table names any longer is RECOVERED from the blocks: an entry deleted but still there. Every offset read from the file is checked against its size and its record.

TIMES. Two FILETIMEs whose meaning depends on the file (libmsiecf, "Use of the FILETIME values"): in a weekly history the secondary one is a LOCAL time, converted with the offset in force at its date; everywhere else UTC. The expiry and last check are FAT date-times, a clock time without a time zone: given as written, never as an instant.

Checked against pymsiecf (libmsiecf's own reader) on public test files of the plaso project (ie_index_dat_test, ie_index_fixtures.sh).
