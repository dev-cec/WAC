Detailed Description

LEVEL 3 OF THE DELETED FILES' RECOVERY: files found in the free clusters by their structure (carving), when even their record is gone (backlog B-036).

WHY ONLY THREE FORMATS. A carved file has no name, no date, no record: only its bytes, cut from a start the signature gives to an end something must give too. Cut wrong, it is a file that looks right and is not — what the recovery must never publish. Only the formats whose own structure gives their exact size, and lets it be checked, are carved:

  • PE (executables, libraries, drivers): the end of the last section's raw data, of the Authenticode signature, or of the COFF symbol and string tables a MinGW build leaves — the headers checked first (machine, sections, alignment); an overlay no header describes (an installer's payload) is cut off;
  • ZIP, and the Office documents and archives built on it: the end of the end-of-central-directory record, which must say where the central directory lies, just before it, starting with its signature;
  • PDF: the first "%%EOF" whose "startxref" points back into the file at a cross-reference table or stream — an incrementally updated PDF is then cut at its first version, which is a whole document too. Anything else — a text, a JPEG, an event log — is left: its end cannot be told from what follows it.

Portable C++: tested natively and under Wine (deleted_files_test).
