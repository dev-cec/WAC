Detailed Description

The SECURITY hive: LSA secrets (names and dates only), cached domain logons, audit policy.

WHAT THE ARTEFACT PROVES.

  • LSA secrets (Policy\\Secrets\\<name>): their NAMES alone are evidence — DefaultPassword (an automatic logon's password stored), _SC_<service> (a service running under an account whose password is kept), NL$KM (cached logons in use), a name no product uses (a tool storing its own). The dates their current and previous values were set (CupdTime, OupdTime) date the change of a password.
  • Cached domain logons (Cache\\NL$1…): how many domain accounts could log on without the domain controller — which accounts is in the encrypted part, not read.
  • Audit policy (Policy\\PolAdtEv): what the machine logs. Its layout is not published: the value is kept as its bytes, undecoded.
  • Account rights (Policy\\Accounts\\<SID>): the privileges (Privilgs, a list of well-known LUIDs) and the logon rights (ActSysAc, a bitmask) held by each account or group. SeDebugPrivilege, SeBackupPrivilege or a remote-logon right granted to an unexpected account is a persistence an attacker leaves here.

WHAT IS NEVER READ. No secret's value, no cached credential: WAC reads names, dates and counts, never what the encryption protects — the same line as for LSASS, which WAC does not dump.
