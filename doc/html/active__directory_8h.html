Detailed Description

The Active Directory database of a domain controller, read in the copy of ntds.dit (active_directory_*.json).

WHAT THE ARTEFACT PROVES. A compromise of a domain is written in its directory: an account added to a privileged group, a delegation or a service principal name set on it, a SID injected in its history, the replication rights granted on the domain that a DCSync needs. Each attribute keeps when it last changed and from which controller; each membership, when it was added or removed; a deleted object stays as a tombstone, its last name and parent kept.

WHAT IS WRITTEN.

  • active_directory_objects.json: one element per object, its name rebuilt up to the root, each attribute under its LDAP name in PascalCase;
  • active_directory_links.json: one element per value of a linked attribute (member…), removed ones included, with its dates and origin;
  • active_directory_replication.json: one element per object and attribute, from replPropertyMetaData: version, date, controller of origin, USNs;
  • active_directory_security_descriptors.json: each distinct descriptor once, which objects name by its SdId (the replication rights are the object ACEs of the domain's root).

THE SECRETS ARE NOT READ. Only the columns of a list of attributes are decoded (ATTRIBUTES, in the source): passwords and keys are never among them, and a new attribute of the schema stays unread until named there. The list is an allowance rather than a refusal because the secrets are many and extensible. The copy of the database itself is a piece of the collection, as a hive is: it holds them encrypted, and is protected as such.

THE FORMAT. datatable holds one row per object (DNT_col its number, PDNT_col its parent's, RDNtyp_col the attribute naming it, OBJ_col false for a phantom) and one column per attribute: "ATT", a letter for its syntax, then its internal identifier. Names are not assumed: the schema in the database itself gives each identifier its LDAP name (attributeSchema) and each class its name (classSchema).

  • a date ("l" syntax) is in seconds since 1601, a "q" one a FILETIME;
  • objectSid and sIDHistory keep their last sub-authority big-endian, so that SIDs sort by RID (measured on objectSid; no controller of the harness holds a sIDHistory, which is written the same way in the published descriptions);
  • a distinguished-name attribute holds the DNT of the object it names;
  • nTSecurityDescriptor holds a number in sd_table, 8 bytes. link_table holds the linked attributes: link_DNT the object bearing the link, backlink_DNT the object named, link_base the attribute (linkID / 2).

THE DATABASE IS COPIED LIVE: the latest changes are only in its logs, collected with it and replayed into the working copy (ese_recovery.h). Measured: without that, objects made after the last checkpoint are absent.

NOT A CONTROLLER: Services\NTDS\Parameters is absent from the SYSTEM hive, nothing was taken, and the files are empty.
